# Vikunja — fleet todo backend

[Vikunja](https://vikunja.io) is the cluster's self-hosted to-do / task-management
app (single Go binary + Postgres, REST/OpenAPI). It is the system-of-record for
the agent fleet's task backlog: each automation keeps its own labelled slice and
Robert gets one aggregated, checkable view.

## Where it lives

`kubernetes/apps/collab/vikunja/`:

- **Pod**: `docker.io/vikunja/vikunja:2.8.0`, port **3456**, app-template HelmRelease,
  `statefulset`.
- **Internal hostname**: `vikunja.${SECRET_DOMAIN}` on the **internal** gateway only
  (no public exposure). There is **no gateway extAuth `SecurityPolicy`** in front of
  it — Vikunja is its own auth gate. This is deliberate: automations call the REST API
  with a Vikunja API token, and a forward-auth gate would reject token requests.
- **Auth**: native OpenID Connect against Authelia (`VIKUNJA_AUTH_OPENID_*`), with
  local + API-token auth kept on (`VIKUNJA_AUTH_LOCAL_ENABLED=true`). Robert logs in
  through the browser via Authelia; automations authenticate with an API token.
- **Database**: `postgres-vikunja` (CNPG, 3 replicas, `ceph-block` PGData, weekly
  Barman backup to Garage — `kubernetes/apps/databases/cloudnative-pg/config/vikunja/`).
  Credentials come from CNPG's generated `postgres-vikunja-app` Secret, reflected into
  `collab` (same emberstack-reflector pattern as Monica).
- **Files PVC**: `vikunja-data-pvc` (Longhorn, 2 replicas, weekly backup + daily
  snapshot) mounted at `/files` (`VIKUNJA_FILES_BASEPATH`). Holds uploaded attachments
  and avatars — irreplaceable, so Longhorn rather than `ceph-block`.

## Secrets

1Password item **`vikunja`** (vault `Kubernetes`), rendered by the inline
`externalSecrets` block in the HelmRelease and by the shared `cnpg-app-database`
component:

| Field | Consumed as | Used by |
|---|---|---|
| `JWT_SECRET` | `VIKUNJA_SERVICE_SECRET` | app — JWT/session signing |
| `OIDC_CLIENT_SECRET` | `VIKUNJA_AUTH_OPENID_PROVIDERS_AUTHELIA_CLIENTSECRET` | app — OIDC client secret |
| `GARAGE_AWS_ACCESS_KEY_ID` / `GARAGE_AWS_SECRET_ACCESS_KEY` | S3 creds | CNPG Barman backup to Garage |

Database username/password are **not** in 1Password — they are generated by CNPG and
reflected from `databases` into `collab`.

## Auth model

- **Robert** → browser → Authelia OIDC → full access (admin via Authelia group).
- **Automations** → REST API with a shared API token → each task carries a per-owner
  label + title prefix so one view can be grouped by owner.

The OIDC redirect URI Authelia must allow is derived from the public URL plus the
provider key: `https://vikunja.${SECRET_DOMAIN}/auth/openid/authelia`.

## SPOF note

Vikunja + its CNPG cluster become a dependency for the fleet's task read/write path.
Mitigations in place: CNPG 3-instance with weekly Barman backup, Longhorn files PVC
with weekly backup, and internal-gateway-only exposure. The app is not on the
household-facing critical path (HA / media / voice), so an outage degrades automation
bookkeeping, not Renee-facing services.

## Troubleshooting

- **Login loops / "invalid state"** — check the Authelia OIDC client redirect URI
  matches `https://vikunja.${SECRET_DOMAIN}/auth/openid/authelia` exactly, and that
  `OIDC_CLIENT_SECRET` in the `vikunja` 1P item matches the Authelia client secret.
- **API token calls 401 at the gateway** — confirm no `SecurityPolicy` was added in
  front of the `vikunja` HTTPRoute; extAuth would block bearer-token API calls.
- **Attachments fail to upload** — `/files` PVC not writable; verify `fsGroup: 1000`
  and that the Longhorn volume is attached/healthy.
- **DB connection errors** — check the `postgres-vikunja-app` Secret is reflected into
  `collab` (the Monica-style reflector annotations on the Cluster) and `postgres-vikunja`
  is `Cluster in healthy state`.
